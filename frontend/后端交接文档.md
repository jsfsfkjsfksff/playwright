## 3. 如何切换到你的后端（最重要的操作步骤）

### 3.1 两个环境变量

复制 `frontend/.env.example` 为 `frontend/.env.local`：

```bash
VITE_API_BASE_URL=http://127.0.0.1:8080
VITE_API_MOCK=false
```

| 变量 | 含义 | 默认 |
| --- | --- | --- |
| `VITE_API_BASE_URL` | 接口基址，末尾斜杠会被自动去掉 | 空（= 未接入） |
| `VITE_API_MOCK` | 是否强制使用本地假数据 | `true` |

运行状态**只在一处判定**（`src/services/config.ts`）：

```ts
API_IS_CONFIGURED = API_BASE_URL 非空 && !API_USE_MOCK   // → 发真实请求
API_DEMO_MODE     = !API_IS_CONFIGURED                    // → 返回本地假数据
```

> ⚠️ **最容易踩的坑**：只填 `VITE_API_BASE_URL` 而不写 `VITE_API_MOCK=false`，**仍然是演示模式**（mock 默认 `true`）。两个都要写。

改完 `.env.local` 必须**重启 dev server**（Vite 的环境变量在启动时注入）。

### 3.2 后端必须允许跨域

开发期前端在 `127.0.0.1:5173`、后端在别的端口 → 属于跨域。前端请求固定带 `credentials: 'same-origin'`、`Content-Type: application/json`，因此你需要在后端放开：

- `Access-Control-Allow-Origin`（`http://127.0.0.1:5173` 或开发期用 `*`）
- `Access-Control-Allow-Methods`: `GET, POST, PUT, DELETE, OPTIONS`
- `Access-Control-Allow-Headers`: `Content-Type, Accept`
- 对 `OPTIONS` 预检直接返回 200

Spring Boot 参考：

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {
  @Override public void addCorsMappings(CorsRegistry registry) {
    registry.addMapping("/api/**")
            .allowedOrigins("http://127.0.0.1:5173")
            .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
            .allowedHeaders("*");
  }
}
```

> 若你把前后端部署在同一域名下（推荐生产做法），则不需要 CORS。

## 4. 前端调用的全部接口（这就是你要实现的清单）

基础路径 `/api/v1`，全部登记在 `src/services/api.ts` 的 `API_ENDPOINTS`。

### 4.1 响应信封（唯一格式）

除播放域那个特殊接口外，**全部**返回：

```json
{ "code": 200, "data": { ... }, "message": "可选，失败时给人看的说明" }
```

- **成功判定：`code === 200`**（写死在 `API_SUCCESS_CODE` 常量，改这里一处即可全局生效）
- 失败时 `code` 非 200，`message` 会被前端**原样展示给用户**，请写成中文可读文案
- HTTP 状态码请仍然正确（2xx / 4xx / 5xx）；非 2xx 会被前端当成网络错误先拦掉

### 4.3 逐接口的请求/响应样例

以下 JSON 都是**前端真实会发出的结构**，可直接当接口文档用。

#### ① POST /api/v1/properties —— 新建资源

```json
// 请求
{
  "type": "CHARACTER",
  "name": "林深",
  "description": "故事的主角",
  "attributes": { "isHostile": false, "age": 27 }
}
```

```json
// 响应（注意：契约只回 nodeId + status，不回完整节点）
{ "code": 200, "data": { "nodeId": "PROP_1001", "status": "CREATED" } }
```

**关键约束**：
- `type` 只能是 `CHARACTER` / `RULE` / `ENTITY`（大写，后端定死）
- `attributes` 是宽松的 `Map<String, Object>`，值可能是布尔/数字/字符串/嵌套对象 —— **请用 `Map<String, Object>` 或 `JsonNode` 接收**，不要建成强类型 POJO，否则前端一旦传入新键就会 400
- 回执**不需要**回传 name/description/attributes，前端会自己拼（它不依赖你回传）

#### ② GET /api/v1/properties?type=CHARACTER —— 资源列表

```json
// 响应：一个干净的数组，不分页
{ "code": 200, "data": [ { "nodeId": "PROP_1001", "name": "林深", "type": "CHARACTER" } ] }
```

**关键约束**：
- `type` 查询参数**可省略**（省略 = 返回所有类型）
- 元素**只回这三个字段**。契约没给 `description` / `attributes` / `status`，也**没有** `GET /properties/{nodeId}` 详情接口
- 前端把缺失字段标成 `null`，卡片上显示「列表接口未返回描述」—— 这是**刻意的**，请不要为了"好看"在列表里塞详情（前端会照样接受，但契约就失真了）
- **如果你愿意补详情字段**：完全兼容，前端会自动显示；但需要同步改 `PropertyListItem` 类型注释

#### ③④ PUT / DELETE /api/v1/properties/{nodeId} —— ⚠️ 契约缺失

```json
// PUT 请求体（与 POST 相同，nodeId 走路径）
{ "type": "CHARACTER", "name": "林深（改）", "description": "...", "attributes": {} }
// PUT 响应：前端假定与 POST 同形
{ "code": 200, "data": { "nodeId": "PROP_1001", "status": "CREATED" } }
// DELETE 响应：data 前端不消费，给 null 即可
{ "code": 200, "data": null }
```

**这两个接口在契约文档里根本不存在**，是前端按 REST 惯例补的。你要么实现它们，要么告诉我方改用别的方案（比如复用 POST 做 upsert）。**不实现的话，真实后端模式下「编辑」「删除」按钮会直接报错。**

#### ⑤ POST /api/v1/voices —— 保存配音配置（播放页选音色）

```json
// 请求（听众在播放页选「女声-温柔」后前端发出的真实抓包）
{
  "characterId": "旁白",
  "voiceName": "female-gentle",
  "promptStyle": "柔和清晰，适合叙事与抒情段落",
  "pitch": 1,
  "rate": 1,
  "timbreId": "female-gentle"
}
```

```json
// 响应：回完整配置对象最理想；回 null 也不会导致前端出错
{ "code": 200, "data": { "characterId": "旁白", "voiceName": "female-gentle", "promptStyle": "...", "pitch": 1, "rate": 1, "timbreId": "female-gentle" } }
```

**字段映射说明（需要你确认，见 6.4）**：
- `characterId`：前端传的是**场景的 `speaker`**（通常就是「旁白」），不是 `PROP_xxxx` 那种资源节点 id
- `voiceName`：前端传的是**音色标识**（`female-gentle`），不是 TTS 引擎的真实发音人名
- `promptStyle`：音色的一句话说明
- `pitch` / `rate`：固定 `1`（播放页只有音色一个可调项，不假装用户调过）
- `timbreId`：**契约里没有这个字段**（文档 2.1 只有前 5 项），前端新增
- 音色标识全集：`male-magnetic` / `female-gentle` / `child` / `narrator-calm` / `elder-warm`

前端对返回体是宽容的（回 `null` 也照样认为保存成功），所以**你的返回体形状不会导致前端崩**，但回完整对象才能让后续「回显」功能用上。

#### ⑥ GET /api/v1/voices/{characterId} —— 查询配音配置

```json
{ "code": 200, "data": { "characterId": "旁白", "voiceName": "...", "promptStyle": "...", "pitch": 1, "rate": 1 } }
```

**404 的语义很重要**：前端把 **HTTP 404** 当作「该角色还没配过音」（不是错误），不弹报错。所以「没配过」请返回 404 而不是 `{code: 500}`。当前**这个接口没有调用方**（见 6.6）。

#### ⑦ POST /api/v1/plan/anchors —— 保存剧情图 ⚠️ 需你确认形状

```json
{
  "nodes": [
    {
      "sceneId": "SCENE_ANCHOR_01",
      "cardName": "雨夜",
      "x": 48,
      "y": 40,
      "text": "雨点砸在车窗上，我看不清前面的路。",
      "speaker": "旁白",
      "audioURL": "https://cdn.example.com/a.mp3",
      "timeStage": 1
    }
  ],
  "edges": [
    {
      "id": "EDGE_SCENE_ANCHOR_01__SCENE_ANCHOR_02",
      "sourceId": "SCENE_ANCHOR_01",
      "targetId": "SCENE_ANCHOR_02"
    }
  ]
}
```

**必须遵守的结构约定（不是风格问题）**：
1. `nodes` 与 `edges` 是**两条互不嵌套的数组**——**严禁** `node.children`、**严禁** `edge.nodes`、**严禁**任何树形结构。层级只靠 id 引用表达。这是为了满足契约里"散点式"的要求。
2. `audioURL` **大写 URL**（编辑态字段），与播放域的 `audioUrl`（小写）**刻意不同**，不要统一。
3. `speaker` 恒为 `"旁白"`（界面上已无说话人选择），但**必须照收**，否则你的 `Scene.speaker` 可能为 null。
4. `cardName` 与 `x`/`y` 契约里没有，要不要入库见 6.3。

```json
// 响应：前端假定回「保存后的锚点数组」
{ "code": 200, "data": [ { "sceneId": "...", "text": "...", "timeStage": 1, ... } ] }
```

前端对这个返回体是宽容的：**不是数组或为空数组时，会保留本地已有锚点**，不会清空。所以回 `null` 也不会把界面弄坏，但就放弃了"以后端为准"的机会。

#### ⑧ POST /api/v1/plan/interpolate —— 一键生成 ⚠️ 返回体未定义

```json
// 请求（严格对应后端 StepRequest 类）
{
  "startSceneId": "SCENE_ANCHOR_01",
  "MustBeSceneId": "SCENE_ANCHOR_05",
  "static": false,
  "outline": "男主试图强行冲卡但失败",
  "layer": 2,
  "maxActions": 3
}
```

**四个致命拼写点（写错就是静默 bug，不会报错）**：
1. `MustBeSceneId` 的 **M 必须大写**。后端用 `@JsonProperty("MustBeSceneId")` 映射，写成 `mustBeSceneId` 会**静默变成 null**。
2. `layer` **没有 s**。
3. `static` 是**布尔**（aigc 是否扩写），不是字符串。
4. `static: true` 时 `layer` **无效**（前端已经把 layer 输入框置灰并注明）。

```json
// 响应：⚠️ 契约未定义，前端目前假定这个形状
{ "code": 200, "data": { "scenes": [ { "sceneId": "SCENE_GEN_01", "text": "...", "speaker": "旁白", "audioURL": "https://...", "timeStage": 2 } ] } }
```

前端只用 `data.scenes[0].sceneId` 决定跳哪个播放页；**拿不到就退回用请求里的 `startSceneId`**，不会报错。所以这个返回体你**可以自由设计**，只要告诉我方最终形状（第 6.5 节）。

另外：**契约没有进度接口**，前端如实显示「已提交，等待后端算完」，不伪造进度条。如果这个接口耗时超过 ~30 秒，建议你考虑加异步任务 + 轮询（这属于契约扩展，需双方确认）。

#### ⑨ POST /api/v1/plan/export-segment —— 导出片段 ⚠️ 返回体未定义

```json
// 请求：sceneIds 顺序 = 时间线顺序（前端不按勾选顺序）
{ "sceneIds": ["SCENE_ANCHOR_01", "SCENE_ANCHOR_02"] }
```

```json
// 响应：⚠️ 契约未定义，前端目前假定
{ "code": 200, "data": { "url": "https://cdn.example.com/export/xxx.mp3" } }
```

契约明确要求「**导出不能由前端直接截取后端返回的 list**」，成品（拼接好的纯音频）必须由后端交付。所以 `url` 必须是**后端拼好的、可直接播放/下载的地址**，前端不做二次拼接。

#### ⑩ GET /api/v1/play/scene/{sceneId} —— 取播放场景 ⚠️ 特殊：裸对象

**这个接口是唯一不走 `{code,data}` 信封的**（契约示例给的就是裸对象）：

```json
{
  "id": 101,
  "sceneId": "SCENE_START_001",
  "text": "雨夜，我站在路口。",
  "speaker": "旁白",
  "audioUrl": "https://cdn.example.com/start.mp3",
  "edges": [
    {
      "action": "向左走",
      "condition": "NONE",
      "targetScene": {
        "id": 102,
        "sceneId": "SCENE_LEFT_001",
        "text": "左边是一条没有路灯的小巷。",
        "speaker": "旁白",
        "audioUrl": "https://cdn.example.com/left.mp3",
        "edges": []
      }
    }
  ]
}
```

前端的兼容策略（`requestFlexibleJson`）：**两种都认**。
- 响应体没有数字 `code` → 当作裸对象，整体就是数据
- 有 `code` 且 `=== 200` → 取 `data`
- 有 `code` 且 ≠ 200 → 抛业务错误并透出 `message`

**⚠️ 三个必须点**：
1. 分支字段名是 **`edges`**，**不是 `choices`**（写错就拿不到分支）
2. `edges[i].targetScene` 里**必须带全**下一层的 `text` / `speaker` / `audioUrl`（契约要求的"零延迟"靠它）
3. 嵌套的 `targetScene.edges` **必须为空数组**——这是契约里的 `@JsonIgnoreProperties("edges")` 行为，前端**依赖**它：先用嵌套数据立刻开播，再补拉一次该场景取分支。**如果你把嵌套 edges 也填满，不会出错**，前端只是会忽略它（`depth > 0` 强制 `edges: []`）。

`audioUrl` 为 `""` 时前端如实提示「该场景没有音频地址，只显示文本」，不会假装能播。

## 6. 需要你决策的问题（阻塞项）

> 这一节是本文档最重要的部分。每条都写明「不解决会发生什么」。

### 6.1 🔴 `POST /api/v1/plan/anchors` 的请求体形状

{ "code": 200, "data": { "nodes": [...], "edges": [...] } }

前端已留好接入点：`stores/studio.ts` 的 `fetchAnchors()`（当前仅演示模式下回读），补上后只需在真实分支里加一次请求，**页面无需改动**。
界面目前**已如实提示**这个缺口（仅真实后端模式显示）。

### 6.3 🟡 `PUT` / `DELETE /api/v1/properties/{nodeId}` 不存在
契约只有 POST 新增 + GET 列表。
**不解决**：资源管理页的「编辑」「删除」按钮在真实后端下会直接报错（现在演示模式下能点通，容易误以为已经能用）。
**请回复**：会实现吗？路径与回执是否接受前端假定的（`{nodeId, status}` / `data: null`）？

### 6.4 🟡 `POST /voices` 的字段语义
前端提交：`characterId` = 场景 speaker（「旁白」）、`voiceName` = 音色标识、`timbreId` = 同值。
**风险**：如果 `characterId` 因为外键约束必须指向 `PROP_xxxx` 资源节点，这个请求会失败；如果 `voiceName` 必须是 TTS 引擎真实发音人名，前端传的值就不能直接用。
**请回复**：`characterId` 用什么？`voiceName` 期望什么格式？`timbreId` 落库键名叫什么？

### 6.5 🟡 `interpolate` / `export-segment` 的返回体
契约只说「返回 200，表示图谱已成功裂变并缝合」，**没定义 data 结构**。前端暂时假定 `{scenes:[...]}` / `{url:"..."}`（容错处理过，形状不对也不会崩）。
**请回复**：最终返回体是什么？前端会据此改 `InterpolateResultData` / `ExportSegmentData` 两个类型（各一行）。

### 6.6 🟡 音色列表接口不存在
契约只有「按角色查询配音配置」，**没有**「可选音色列表」。前端 `getVoiceList()` 是**占位实现，不发任何请求**，直接返回内置 5 项。
**不解决**：音色选项写死在前端。若将来要由后端配置音色，需你提供一个列表接口（例如 `GET /api/v1/voices/timbres`）。
目前**不影响主流程**，可以不阻塞交接。

### 6.7 🟡 没有进度通道
`interpolate` 是同步等待（HTN 演算 + 剧情渲染 + TTS 合成都在一次响应里）。前端不做假进度，只有一个不确定时长的等待过场。
**建议**：若实测超过 ~30 秒，考虑异步任务 + 轮询，双方再定协议。

## 7. 几个容易被后端忽略的前端细节

### 7.1 播放页的分支策略（依赖你的嵌套结构）

前端是这样用 `GET /play/scene/{id}` 的：

```
用户点分支
  → 用 edges[i].targetScene（已带全数据）立刻开播，不转圈   ← 依赖你把 targetScene 填满
  → 同时补拉一次 GET /play/scene/{新 sceneId} 取它的 edges  ← 依赖你把嵌套 edges 清空
  → 如果这一段还在播，则追加进播放队列，播完自动接上（不打断当前句）
```

所以：
- **`targetScene` 一定要把 `text` / `speaker` / `audioUrl` 填满**（不然点了分支只能退化成再请求一次，会有延迟）
- **补拉分支请求会真实发生**（每个分支点多一次 GET），请确保这个接口足够轻
- 补拉失败**不打断收听**，只在页面提示「后续分支未取到」

### 7.2 字幕：契约没有逐句时间戳

契约的场景对象**只有** `text / speaker / audioUrl`，**没有任何字幕时间戳**。
前端因此：
- 默认把 `text` 按句末标点切句，再**按句长比例**把音频总时长分配给各句
- 内部把这一事实暴露成 `timelineIsEstimated`（**当前播放页并未渲染字幕**，因此这个标记暂时没有消费者）

**如果你想让我方尽快把字幕做准**，请补一个字段，前端会自动采用（`readPlayScene` 已经支持三种格式）：

```json
// 推荐：结构化数组
"subtitles": [
  { "text": "雨夜，我站在路口。", "start": 0.0, "end": 2.4 },
  { "text": "远处有车灯晃过来。", "start": 2.4, "end": 5.1 }
]
```

也支持直接给 LRC / SRT / WebVTT / JSON 四种文本格式的字符串（有现成解析器 `utils/subtitles.ts`）。

### 7.3 `timeStage` 的语义是并排，不是串行

`timeStage` 是**数字坐标**：**越小越靠前，数字相同 = 时间线上绝对并列**（并排渲染，用于并列结局/不同视点）。
前端提交的是数字，**请勿改成字符串或"第一幕"这类文案**——排序与并排判断都依赖数值比较。

### 7.4 音频必须能被 `<audio>` 直接播放

前端用的是原生 `<audio :src="audioUrl">`，**没有**经过 Web Audio 解码。因此：
- `audioUrl` 必须是浏览器 `src` 能直接吃的东西（mp3 / m4a / wav 等，或可访问的 URL）
- **必须处理 Range 请求**（大文件拖动进度条依赖 206 Partial Content）
- 跨域音频若同源部署则无问题；若音频在 CDN，需允许跨域（否则只是不能做音频分析，播放本身 OK）

### 7.5 剧情回环（A→B→A）已被处理，但请确认你的数据允许

前端补拉分支时**按下标定位**（不是按 sceneId 查），因为回环会让队列里出现重复 sceneId。后端只要不把回环判成"数据错误"即可。

## 8. 部署注意事项

1. **HTML5 History 模式**：路由没有 `#`。部署到静态服务器时，**必须把未知路径回退到 `index.html`**，否则直接访问 `/player/SCENE_XXX` 会 404（Nginx 用 `try_files $uri $uri/ /index.html`）。
2. **前端是纯静态产物**：`npm run build` 输出 `dist/`，交给 Nginx 或后端静态资源即可，无 Node 运行时要求。
3. **同源部署最省事**：把 `dist/` 与 `/api/v1` 放同一域名下，可同时省掉 CORS 与 Cookie 问题。
4. **环境变量是构建期注入**：`.env.local` 的内容被**打进产物**。不同环境要分别构建，或改用运行时配置（当前未实现）。

## 10. 前端对错误处理的约定（请照着错误信息写 `message`）

| 前端行为 | 说明 |
| --- | --- |
| HTTP 非 2xx | 前端统一抛「接口返回异常状态：{status}」，**`message` 就看不到了** → 请尽量用 200 + 非 200 的 `code` 表达业务错误 |
| `code !== 200` | 展示后端给的 `message`（没有则显示「接口返回业务失败码：{code}」） |
| 看不到 `data` | 某些接口缺失 `data` 会被提示「响应体缺少 data 字段」 |
| 404（仅 `GET /voices/{id}`） | 被当作「该角色未配置」，**不报错** |
| 网络失败/超时 | 提示请求失败，页面提供「重试」 |

**建议**：所有业务错误都用 `{ "code": <非200>, "message": "中文可读说明" }` + HTTP 200，这样用户能直接看到你的文案。
